# A production playbook for compelling Shorts

Research and workflow revision: **5 November 2026**.

The useful part of “clickbait” is a promise that makes someone want the next piece of information. Build that promise around a specific subject, make progress visible, and deliver an answer worth the wait. For this repository, the target is **curiosity that the video satisfies**. A bigger caption or louder narrator is a presentation choice; the story still needs a reason to continue.

This playbook turns reference study into an original production method. Its recommendations are working hypotheses, not a formula proven to produce a particular view count.

The strongest overlap is **premise → question → meaningful progression → payoff**. The channels execute it differently. Our sample includes object explanations, transformations, tasks and visual comedy; it also includes moments without dialogue captions and an explicit late subscription prompt. The research therefore does not support universal rules such as “cut every second,” “fill the whole background,” or “every ending must loop.” See the linked study for the actual evidence.

## 1. Choose a premise that can be seen and retold

Start with a specific subject doing or revealing one surprising thing. A topic is the territory; a premise describes the event or question inside it.

| Weak starting point | Stronger original premise | What the picture must supply |
|---|---|---|
| “Data centres are controversial.” | “The cloud needs real buildings. Why are some neighbours pushing back?” | A useful digital service and its physical facility near people |
| “An amazing building challenge.” | “Can this paper bridge hold a toy car?” | The actual bridge, car, constraints and test result |
| “You won't believe this transformation.” | “Can this empty corner become a reading nook using only what's already here?” | The starting condition, available objects and finished result |

These are new planning examples, not verified experiments or scripts ready for factual publication. Write the answer before committing to the opening. If the result is unknown, plan honest possible endings instead of pretending one is guaranteed.

Use the [production brief](../templates/SHORTS_BRIEF.md) to record the viewer, promise, evidence and payoff. Keep the central question specific enough that the last scene can answer it.

## 2. Replicate a mechanism that fits the subject

The following are our adaptations of the [observed formats](research/shorts-channel-study.md). Choose a structure; write original lines, characters, images and outcomes.

| Format | Reusable sequence | Best fit | Key requirement |
|---|---|---|---|
| Hidden mechanism | Familiar object → puzzling feature → plausible interpretation → physical explanation | Science, design, infrastructure | The explanation must be accurate and visually understandable. |
| Concrete challenge | Goal + constraint → attempts → obstacle/decision → visible result | Builds, tests, journeys | Define success before showing the result. |
| Transformation | Before state → process → consequential setback → after state | Making, restoration, learning | Show comparable before/after evidence. |
| Escalating visual variation | Readable situation → changed version → more consequential variation → comic or meaningful payoff | Character scenes, comparisons | The changing variable should remain easy to identify. |
| Causal explainer | Familiar benefit → hidden dependency → local consequence → response/tradeoff → answer | Public-interest topics, history | Preserve counterpoints and uncertainty alongside the claims. |
| Satisfying loop | Clear action → completed transformation → natural visual return | Animation, processes | Completion should still feel complete on one watch. |

Loops also draw on [Kevin Parry's direct account](https://creatorscience.com/podcast/kevin-parry/) of constructing replayable animation. That does not establish an algorithmic benefit for every loop.

For the current data-centre topic, use the causal-explainer format with a familiar-object opening. The [worked blueprint](../production/data-centres-natural/RETENTION_BLUEPRINT.md) maps this to existing assets and scene IDs. It is a proposed edit plan, not a replacement narration or newly rendered film.

## 3. Design the opening image, line and payoff together

Write three opening options. For each, identify:

1. **What is visibly happening?** The viewer should locate the relevant subject without reading an introduction.
2. **What is unusual or consequential?** Use a concrete contrast, constraint, outcome or question.
3. **What will this video deliver?** Promise only what the ending can show or explain.

Select for comprehension as well as surprise. An opening that looks dramatic but makes an unsupported claim is a broken promise. A misleading building explosion cannot stand in for a policy dispute; a household bill cannot visually double when the source concerns a global electricity-demand projection.

An immediate opening is supported by the [Jenny Hoyos/YouTube discussion](https://blog.youtube/creator-and-artist-stories/youtube-shorts-deep-dive/). Its first-second advice is a creative heuristic. Treat the first moving frame as the feed entrance; a title or cover still cannot carry context the opening omits. Do not turn that heuristic into a mandatory timer for every explanation.

## 4. Make the middle change something

Fill the [beat sheet](../templates/SHORTS_BEAT_SHEET.md) before building detailed scenery. Each beat should add an observation, decision, obstacle, explanation or consequence. Ask what the viewer now understands that they did not understand before.

Use causal connections: **this happens, therefore something changes; but a constraint changes the next decision**. Avoid a list of disconnected impressive facts. This approach and the need for processing room are described in [Jenny Hoyos's direct interview](https://creatorscience.com/podcast/jenny-hoyos/); they are not a requirement to speak those conjunctions aloud.

For an original paper-bridge demonstration, a useful outline is:

| Beat | New information | Visible evidence |
|---|---|---|
| Promise | Will this specific paper bridge support this toy car? | The car beside the initial bridge |
| First attempt | What happens under the first test? | The real test, including failure if it occurs |
| Decision | What single design change is being tried, and why? | A clear comparison with the previous structure |
| Payoff | Did the changed design succeed under the stated conditions? | The complete result, followed by a brief qualified explanation |

Do not invent the outcome or omit a condition that changes what the test means. The same discipline applies to animation: a rendered illustration can explain an idea, but it is not experimental evidence.

## 5. Edit for information and emotion

Use cuts, reframing, movement, sound and text to direct attention to the changing idea. A closer view can reveal a mechanism; a wider view can reveal who is affected; a reaction can let a consequence register. Choose the change for that purpose.

**Pacing is the rate of meaningful change, with enough time to understand it.** A clear hold may do more than three decorative cuts. Remove redundant setup and dead space; keep pauses that support a reveal, reaction or difficult explanation. Avoid stacking a crucial number, a new term and an unrelated visual joke in the same moment.

Give each shot a primary subject. Populate the environment to establish place, scale and the people involved. Use quieter background motion during important explanations. For this repo's 3D scenes, inspect the actual portrait camera view: adding fifty hidden buildings does not create visible depth. Follow the [background study](shorts-background-research.md) and preserve the [roof-flicker repair](data-centres-lighting-fix.md).

These are editorial decisions, not measured cuts-per-second or motion-density targets. The frame samples cannot support such measurements.

## 6. Make voice, sound and captions cooperate

**Voice:** mark each line's intent—curiosity, surprise, concern, explanation or resolution. Record or synthesize a natural take with emphasis and breaths that match the meaning. Listen for a change in thought, not merely higher speed. Derive animation timing from the selected take; do not time-compress narration to fit a predetermined duration. Natural, personal delivery also appears in the [Jordan Howlett/YouTube discussion](https://blog.youtube/creator-and-artist-stories/five-tips-to-master-shorts/).

**Sound:** choose a small set of motivated cues: the action, the connection becoming clear, the important impact, the final result. Let music and ambience establish tone while speech remains intelligible. A quiet moment can provide contrast. Set gains after listening to the actual stems; a universal music boost is inappropriate across different recordings. [YouTube's editing guidance](https://support.google.com/youtube/answer/13380879?hl=en) supports sound, text and voiceover serving the story; it does not specify this repo's mix levels.

**Captions:** the user's requirement remains full, verbatim subtitles synchronized to the spoken script. Use the existing compact dark boxes, bold type and current-word highlight. Phrase breaks should make the sentence easy to read; they must not delete qualifiers, change wording or create a second competing headline. Keep the evidence and character faces clear. Exact parameters and regeneration steps live in [SUBTITLES.md](../production/data-centres-natural/SUBTITLES.md).

Review a phone-sized version with sound, then muted. Muted review checks visual clarity and subtitle access; it does not mean the whole explanation must be duplicated as graphics.

## 7. Deliver the promised result

The final answer can be a working mechanism, a finished object, a resolved comparison, or a clear account of why the situation happens. Give that answer time to register. Remove an outro that adds nothing to this story; if a call-to-action has a purpose, test it rather than assuming it always helps or hurts.

An optional callback can show the first image with new meaning. A seamless loop is suitable only when it serves the experience. Do not hide the answer behind another replay or a promised second part. The sample includes different ending treatments, so “stop instantly” and “always loop” are not research findings.

## 8. Turn the brief into a reproducible production

1. Copy the [brief](../templates/SHORTS_BRIEF.md) and [beat sheet](../templates/SHORTS_BEAT_SHEET.md) into `production/<project>/`, adjusting their links. Record claims, sources, chosen format, opening options and payoff.
2. Finalize the script and native voice take. Save measured word times; review names, punctuation and alignment. Rough beat windows are not recording timestamps.
3. Create or update the composition and scene timeline. Follow [SKILL.md](../SKILL.md) for the Remotion/three.js workflow, entry registration, world, characters and postprocessing. Choose duration from the actual story and take.
4. Rebuild dependent captions and sound cues whenever wording or timing changes. In the current natural example, `timeline.json` does **not** automatically rewrite `src/videos/data-centres/natural-story.ts`; synchronize it explicitly. The [blueprint dependency table](../production/data-centres-natural/RETENTION_BLUEPRINT.md#production-dependencies-for-a-future-implementation) lists the affected files.
5. Check representative stills, consecutive motion around transitions, phone readability and the complete audio mix. Fix technical artifacts before judging creative impact.
6. Record what was rendered, what was inspected and what remains a hypothesis in the production notes. Only call a change an audience improvement after collecting audience evidence.

For an edit to the existing natural composition:

```sh
npm run subtitles:data-centres
npm run subtitles:check
npm run typecheck
npm run render:data-centres:natural
```

These commands regenerate/check subtitles and render the **current** inputs. They do not implement the proposed blueprint or create a new voice take by themselves. For a new project, adapt the commands and composition rather than overwriting this example.

## 9. Learn from results without inventing a viral formula

Write one testable hypothesis before release: for example, showing a physical consequence before an abstract topic may make the opening easier to understand. Keep a record of what changed and what remained comparable.

After an authorized publication, compare the choice to stay with viewing duration, percentage viewed and retention around the planned beats. Read confusing comments alongside the picture and sound at those moments. Public totals alone cannot isolate the effect of a caption, hook or voice. The [measurement guide](research/shorts-measurement.md) provides current definitions, a four-Short directional comparison and a reusable results log.

The production pass is complete when the promise is clear, the evidence supports it, each beat advances it, the payoff fulfils it, and the rendered picture and audio communicate it cleanly. Reach remains an outcome to measure.
